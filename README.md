# source-shift

> AI가 프로그램을 생성하고 수정하는 데 가장 효율적인 표현을 탐구한다.

GitHub: [JooWon0712/source-shift](https://github.com/JooWon0712/source-shift) · 공개 저장소

source-shift는 같은 요구사항을 고수준 소스와 저수준 표현으로 각각 생성하게 하고, 정확도와 전체 작업 비용을 비교하는 실험 프로젝트다.

프로젝트 표기·폴더·저장소 이름은 `source-shift`로, 일반 문서 파일명은 소문자 kebab-case로 통일한다. `README.md`와 `AGENTS.md`는 도구가 찾는 표준 파일명을 유지한다.

출발점은 다음 질문이다.

> 사람이 코드를 직접 읽는 일이 줄어든다면, AI는 계속 사람이 읽기 좋은 언어로 프로그램을 작성해야 할까?

**현재 상태: 실행·채점 기반, usage 복원, 로컬 변환·런타임 측정을 구현하고 테스트 64개를 통과했다. 후속 묶음 파일럿에서는 C/WAT 각각 3회 생성한 코드가 사후 평가 4,284건을 모두 통과했고 수정은 없었다. 생성 비용의 캐시 통일 환산은 C가 중앙값 약 8% 낮아 사전 기준을 충족했다. WAT는 조립이 빠르고 파일이 작았으며 warm 실행 속도는 과제별로 갈렸다. 실제 청구액은 미관측이다.**

2026-10-27 사용자 요청으로 이번 작업을 마감했다. 작업의 이유부터 실험 시나리오·결론·후속 판단까지는 [종합 정리](docs/project-summary.md), 운영상 재개 지점은 [작업 인계](docs/session-handoff.md)에 모았다. 새 실험·조사는 진행하지 않는다.

## 첫 번째 가설

고수준 소스를 생략한 생성 경로가 같은 정확도를 유지하면서 생성과 수정의 총비용 또는 총시간을 줄일 수 있는지 확인한다.

첫 비교는 다음 두 경로다.

| 경로 | 생성부터 실행까지 |
| --- | --- |
| C 경유 | 자연어 명세 → 클라우드 모델이 C 함수 본문 생성 → Clang으로 Wasm 컴파일 → Wasmtime 실행 |
| WAT 직접 생성 | 같은 명세 → 같은 모델이 WAT 함수 본문 생성 → Wasm 조립 → 같은 Wasmtime 실행 |

WAT는 WebAssembly 명령의 텍스트 표현이다. 이 실험에서 모델은 바이너리 바이트를 직접 출력하지 않는다. WAT 경로에도 조립·검증·런타임 컴파일이 필요하다. 두 파이프라인의 차이를 측정하며, 결과만으로 인간용 문법 자체의 인과 효과를 단정하지 않는다.

## 첫 구현의 완료 조건

명세 10개를 두 경로로 처리한 뒤, 성공과 실패를 모두 포함한 정확도·토큰·시간·수정 횟수 비교표를 재현 가능하게 생성한다.

이 10개는 실험기 점검용 파일럿이다. 일반적인 코드 생성 능력이나 비용 우월성에 대한 결론은 별도의 평가 문제와 반복 실행으로 확인한다. 가설에 불리한 결과도 정상적인 실험 결과다.

현재 세션 기반 묶음 파일럿은 성공·실패 기록, 실제 usage, 에이전트 턴 시간과 도구별 측정을 연결했다. 생성기 비교 외의 조율·측정기 구현·주 에이전트 분석 사용량도 별도로 공개했다. 순수 모델 요청 지연, 백엔드 모델 snapshot과 실제 청구액은 미관측이다. 결과의 범위는 개발용 10과제와 현재 모델·전달 방식에 한정하며, 별도 평가에서 일반적인 우월성을 확인한 것은 아니다.

## 개발 방향

실험 진행·채점 기반은 Python으로 구현했고 첫 실행 대상은 Wasm, 실행기는 Wasmtime이다. 모델은 사용자가 선택한 클라우드 모델을 기본으로 하며, 실제 호출 방식과 실행 예산은 모델 연동 전에 명시한다. 새 모델 학습이나 로컬 대화 LLM 환경은 첫 실험에 필요하지 않다.

첫 비교 후에는 필요에 따라 구조화된 AST/IR 경로를 추가한다. 범용 언어, 자체 VM, raw byte 생성, UI·패키지 생태계는 후속 연구 후보로 둔다.
