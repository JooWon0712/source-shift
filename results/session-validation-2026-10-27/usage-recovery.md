# 기존 세션 로그에서 복원한 토큰 사용량

확인일: 2026-10-27, Asia/Seoul. 새 코드 생성이나 유료 API 실험을 반복하지 않고 기존 생성기 20개의 로컬 사용량 기록을 분석했다. 초기 보고서 작성 시 도구 응답에 없던 사용량과 모델 설정을 추가로 확인한 것이다.

로그에 기록된 모델 별칭은 `gpt-6.1-sol`, 추론 설정은 `ultra`이며 20개 생성기에서 같았다. 백엔드 모델 snapshot과 공급자 API 원 응답은 확인하지 못했다.

| 항목 | C 생성기 10개 | WAT 생성기 10개 | 합계 |
| --- | ---: | ---: | ---: |
| 입력 토큰, 캐시 포함 | 927,379 | 897,309 | 1,824,688 |
| 위 입력 중 캐시된 토큰 | 851,456 | 869,632 | 1,721,088 |
| 위 입력 중 비캐시 토큰 | 75,923 | 27,677 | 103,600 |
| 출력 토큰, reasoning 포함 | 2,133 | 3,262 | 5,395 |
| 위 출력 중 reasoning 토큰 | 246 | 918 | 1,164 |
| 입력 + 출력 토큰 | 929,512 | 900,571 | 1,830,083 |
| 도구 호출·완료 보고를 포함한 모델 응답 수 | 29 | 28 | 57 |

캐시 입력을 입력에 다시 더하거나 reasoning을 출력에 다시 더하지 않는다. 코드 생성 시도는 20개이고 테스트 피드백에 따른 수정 호출은 0회였다. 57은 도구 사용·파일 저장·완료 보고까지 포함한 모델 응답 수다.

이 집계는 **생성기 20개만** 포함한다. 주 에이전트, 개발, 실행·검증 준비, 검색과 보고서 작성의 사용량은 포함하지 않는다. 입력은 전체 지시문·도구 설명과 도구 왕복 문맥을 포함하므로 짧은 생성 본문의 토큰 수와 다르다.

## 집계 근거

현재 채팅의 자식 생성기 경로 `/root/trial_p01_c`부터 `/root/trial_p10_wat`까지를 선별했다. 각 `token_usage_record`를 thread/response 식별자로 중복 제거하고 개별 `usage`를 합산했다. 생성기별 합계가 마지막 `thread_token_usage`와 20개 모두 일치했다. 누적 `event_msg` 값을 다시 더하지 않았다.

[usage-recovery.json](usage-recovery.json)에 숫자와 집계 조건을 저장했다. 원시 로그, 개인 경로와 계정 식별자는 공개 사본에 넣지 않았다. 최초 측정 시점의 `summary.json`은 그대로 보존하며 추가 관측은 이 파일에 기록한다.

## 금액 환산과 해석

2026-10-27 [공식 API 가격표](https://developers.openai.com/api/docs/pricing)의 `gpt-6.1-sol` Standard/짧은 문맥 단가인 100만 토큰당 일반 입력 $2, 캐시 입력 $0.10, 출력 $10을 가정하면 합계는 **약 $0.43**이다. 관측된 cache-write 토큰은 0이었다. 이는 가상 API 조건의 환산이며 **실제 Codex 구독 청구액이나 한도 차감량을 측정한 값이 아니다.**

캐시 적중률은 C 약 91.8%, WAT 약 96.9%로 달랐다. 최초 3개는 프롬프트를 직접 전달했고 나머지는 파일을 읽게 했으므로 도구 왕복 횟수도 동일하지 않았다. WAT의 출력 토큰은 더 많았지만 이 조건에서의 단가 환산액은 캐시 차이에 영향을 받았다. 이 실행으로 표현 자체의 비용 우열을 판단하지 않는다.

다음 비교는 전달 방식·도구·모델 설정·문맥·출력 상한을 같게 하고 C/WAT 순서를 교차해야 한다. 먼저 2과제 × 두 경로로 집계를 점검한 뒤, 개발용 10과제 × 두 경로 × 3회 반복을 하면 최초 생성 60회다. 각 생성에 수정 최대 2회를 허용하면 생성·수정 요청은 최대 180회다. 통신 재시도는 끄거나 별도 요청으로 예산에 포함하며 실패 사용량도 보존한다. 일반화 평가는 개발에 사용하지 않은 별도 문제로 진행한다.
