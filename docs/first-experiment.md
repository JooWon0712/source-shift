# 첫 실험 계획: C 경유와 WAT 직접 생성

- 실험 ID: `SS-001`
- 문서 상태: 실험 계획 초안, 실행·채점 기반 및 세션 생성 검증 완료
- 기준일: 2026-10-27
- 실행 상태: 자동 테스트 64개 통과. 초기 세션 검증 및 후속 묶음 파일럿의 공개·비공개 사후 평가 완료. 별도 API를 통한 통제 비교는 미실행

## 1. 연구 질문

같은 자연어 기능 명세를 같은 클라우드 모델에 주었을 때, C 함수 본문을 생성해 Wasm으로 컴파일하는 경로와 WAT 함수 본문을 생성해 Wasm으로 조립하는 경로의 정확도·총토큰·총시간·수정 비용은 어떻게 다른가?

주 가설은 WAT 경로가 같은 정확도를 유지하면서 생성 또는 수정의 총비용을 줄일 수 있다는 것이다. 반대 결과와 차이가 불명확한 결과도 허용한다.

이 실험은 모델이 raw binary bytes를 직접 출력하는 실험이 아니다. 또한 컴파일러와 표현의 차이가 함께 존재하므로, 관측 차이를 인간 가독성만의 효과로 해석하지 않는다.

## 2. 범위와 인터페이스

- 외부 부작용이 없는 결정적인 정수 순수 함수만 다룬다.
- 공통 인터페이스는 `solve(a: i32, b: i32, c: i32) -> i32`다. 사용하지 않는 인수는 0을 넣는다.
- C는 `int32_t`, Wasm은 `i32`를 사용하고 반환값은 signed 32-bit 정수로 해석한다.
- 입력 범위는 과제별로 제한한다. 정상 구현의 산술 중간값과 결과가 signed 32-bit 범위를 넘지 않도록 한다.
- 부동소수, 문자열, 배열·직접 메모리 접근, 재귀, 파일·네트워크, 외부 라이브러리 호출은 첫 실험에서 제외한다.
- C 헤더·함수 시그니처와 WAT 모듈·export·인수 템플릿은 실행기가 제공한다. 모델은 본문만 생성한다. WAT의 로컬 변수 선언은 본문의 허용 영역으로 둔다.
- 생성 본문과 템플릿을 합친 산출물을 모두 보관한다. 검증되지 않은 자동 수정으로 모델 결과를 조용히 고치지 않는다.

제한된 도메인 밖의 동작은 이 실험의 정확성 주장에 포함하지 않는다. 테스트 통과는 전체 의미 보존이나 정의되지 않은 동작의 부재에 대한 증명이 아니다.

## 3. 파일럿 과제 10개

| ID | 기능 | 입력 범위와 계약 | 중요한 경계 |
| --- | --- | --- | --- |
| P01 | 세 정수의 합 | `a,b,c ∈ [-1000,1000]` | 음수, 0, 상쇄 |
| P02 | 세 정수의 최댓값 | `a,b,c ∈ [-1000,1000]` | 동률, 모두 음수 |
| P03 | 범위 제한 | `a,b,c ∈ [-1000,1000]`, `b <= c`; `a`를 `[b,c]`로 제한 | 경계와 같은 값, 폭 0 |
| P04 | 절댓값 | `a ∈ [-1000,1000]`, `b=c=0` | 음수, 0 |
| P05 | 부호 판정 | `a ∈ [-1000,1000]`, `b=c=0`; 결과는 `-1,0,1` | -1, 0, 1 |
| P06 | 0부터 n까지 정수 합 | `a=n ∈ [0,1000]`, `b=c=0` | n=0, 1, 1000 |
| P07 | 팩토리얼 | `a=n ∈ [0,12]`, `b=c=0`; `0! = 1` | n=0, 1, 12 |
| P08 | 최대공약수 | `a,b ∈ [0,10000]`, `c=0`; `gcd(0,0)=0` | 한쪽 0, 동률, 서로소 |
| P09 | 십진수 자릿수 | `a ∈ [0,1000000000]`, `b=c=0`; 0의 자릿수는 1 | 0, 9/10, 99/100 |
| P10 | 소수 판정 | `a ∈ [0,10000]`, `b=c=0`; 소수면 1, 아니면 0 | 0, 1, 2, 제곱수 |

이 과제들은 도구·채점·기록 검증용이다. 널리 알려진 간단한 문제이므로 일반화나 새로운 알고리즘 합성 능력의 근거로 삼지 않는다.

각 과제에 생성 모델이 볼 공개 예제와 최종 채점용 비공개 입력을 별도로 준비한다. 경계값·고정된 난수 입력·독립 참조 구현으로 기대값을 점검한다. 비공개 테스트는 생성·수정 프롬프트에 넣지 않는다.

| 생성 예산 | 동일한 출력 상한과 수정 기회. 파일럿에서 상한 적합성을 확인한 뒤 평가 전에 고정 |

| 순서·반복 | C/WAT 순서를 교차 또는 무작위 배정. 평가 단계는 과제·경로당 최소 3회 실행을 계획 |

Clang의 최적화와 WAT 조립은 같은 작업이 아니다. C `-O0` 결과를 추가할 경우 같은 생성 C를 재컴파일한 진단 자료로 구분하며, 주 비교와 섞지 않는다. Wasmtime의 JIT 조건이 같아도 두 입력의 선행 최적화가 같다는 뜻은 아니다.

한 경로에만 제한을 늘리거나 더 많은 예제·수정 기회를 제공하지 않는다. 설정을 변경하면 새로운 실험 버전으로 기록한다.

## 5. 실행 절차

1. 명세·공개 예제·비공개 테스트·참조 구현을 검토하고 버전을 고정한다.
2. 고정된 템플릿과 명세로 C 또는 WAT 본문을 생성한다.
3. 본문을 변환·검증하고, 유효하면 공개 테스트를 실행한다.
4. 실패 시 변환 오류 또는 공개 테스트 실패 정보를 정해진 형식으로 반환한다. 최대 2회 수정한다.
5. 생성·수정 루프가 끝난 뒤 비공개 테스트로 최초·각 수정·최종 산출물을 각각 채점한다. 변환에 실패한 산출물도 실패로 집계한다. 이 평가 결과는 모델에 전달하거나 다시 수정 루프에 넣지 않는다.
6. 원 응답, 산출물, 모든 호출의 usage, 오류, 타임스탬프와 판정을 저장한다. 성공 여부와 무관하게 기록한다.
7. 같은 조건의 다른 경로와 반복 실행을 수행한다.
8. 비교표와 실패 유형을 생성하고, 설정·누락값·한계를 함께 출력한다.

최초 응답의 정확도와 수정 후 최종 정확도는 같은 비공개 테스트 기준으로 따로 집계한다. 중간 산출물의 사후 평가도 가능하게 원본을 보존한다. 비공개 테스트에서의 성능은 평가용이지 추가 튜닝 신호가 아니다.

## 6. 후속 기능 변경 실험

버그 수정과 완성된 프로그램의 기능 변경은 구분한다. P02, P06, P09에 다음 변경을 적용하는 소규모 파일럿을 계획한다.

| 기반 과제 | 변경 요청 |
| --- | --- |
| P02 | 세 정수의 최댓값 대신 최솟값 반환 |
| P06 | 0부터 n까지 모든 정수 대신 짝수만 합산 |
| P09 | 십진수 대신 이진수 자릿수 반환. 0의 자릿수는 1 |

두 경로 모두 원본을 정답으로 완성한 경우에만 paired 기능 변경 비교에 포함한다. 포함·제외된 과제 수를 공개하여 쉬운 성공 사례만으로 결과를 과장하지 않는다.

새 독립 문맥에 원래 명세·완성된 대상 표현·변경 요청을 제공하고, 변경된 공개/비공개 테스트를 사용한다. 이 단계도 초기 변경 응답 1회와 버그 수정 최대 2회를 허용한다. 비용은 최초 생성 단계와 분리한다. 전체 개발 생애주기의 비용을 합산할 때는 포함 범위를 명시한다.

## 7. 기록할 지표

| 구분 | 지표 |
| --- | --- |
| 정확도 | 첫 응답의 테스트 통과율, 수정 예산 내 최종 통과율, 과제별 성공 수 |
| 토큰 | 모든 호출의 입력·출력·확인 가능한 reasoning·캐시 관련 usage. 제공자가 합산하는 항목은 중복 합산하지 않음 |
| 시간 | 모델 요청 wall-clock, 변환·검증, 공개 테스트, 최종 채점, 처음부터 최종 판정까지의 총시간 |
| 수정 | 수정 호출 수, 오류 유형, 동일 오류 반복 여부 |
| 비용 | 확인 가능한 실제 과금 또는 명시한 단가의 추정. 둘을 구분하고 기준일 기록 |
| 산출물 | 본문/전체 파일 크기, 생성물 토큰 수, Wasm 크기 |
| 실행 성능 | 성공 산출물만 별도 측정. cold start와 warm 반복을 분리하고 입력·런타임 조건 기록 |
| 변경 용이성 | 기능 변경 실험의 성공률·총토큰·총시간·수정 횟수 |

실패한 실행도 총소비량에 포함한다. 전체 소비 비용을 성공 문제 수로 나눈 값도 함께 제시하며 성공 수가 0이면 계산 불가로 둔다. 성공 사례만의 평균은 보조 지표로 표시한다.

누락된 usage나 관측할 수 없는 내부 reasoning은 `null` 또는 미관측으로 기록한다. 파일 길이를 실제 usage로 대체하거나, 합산된 usage에서 reasoning을 다시 더하지 않는다. 출력 토큰 절감률을 전체 비용 절감률로 바꾸어 주장하지 않는다.

게임 등 다른 CPU 부하가 있으면 환경 기록에 남긴다. 게임을 중지하거나 상시 감시하지 않는다. 실행 성능의 신뢰할 만한 측정이 어려우면 해당 항목을 보류한다.

## 8. 단계별 구현 산출물

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| A | 실험 계약과 도구 확인 | 모델 호출 방식·예산, 의미 규칙, 도구 버전과 제한을 명시 |
| B | 모델 없는 실행기 | 직접 작성한 C/WAT 예제로 변환·실행·실패 처리가 동작 |
| C | 과제·참조 구현 | 파일럿 10개와 공개/비공개 테스트 검토 완료 |
| D | 생성·수정·기록 | 두 경로를 동일 계약으로 호출하고 모든 시도를 저장 |
| E | 파일럿 보고서 | 10개 과제의 비교표와 실패 원인, 미측정 항목 생성 |
| F | 별도 평가 | 개발에 쓰지 않은 20~30개 과제와 반복 실행. 조건 변경 전 고정 |
| G | 해석과 후속 결정 | 관측 차이·불확실성·일반화 한계와 후속 계획 기록 |

첫 버전의 진행·채점 기반은 Python으로 구현했다. 현재는 파일럿 과제·참조 구현, 고정 C/WAT 템플릿, 변환·실행기, 수동 본문 채점 CLI와 시도별 JSON 기록이 있다. Wasmtime 의존성은 `pyproject.toml`에 고정했다. 사용법과 개발 기본값은 [모델 없는 실행기](local-runner.md)에 정리한다.

단계 A의 통제 실험용 API 호출 방식·예산은 미정이다. 단계 B의 수동 예제 검증과 단계 C의 과제·참조 구현을 완료했고, 세션 에이전트의 파일 응답을 공개 검사·수정 프롬프트·사후 평가·요약으로 연결하는 `scripts/session-trial.py`를 추가했다. 제외 기능의 완전한 정적 검사, API 생성 어댑터, 실제 usage 기록기, 별도 평가 문제와 통제 비교를 위한 계약 고정은 남아 있다.

2026-10-27에는 현재 세션의 모델 설정을 상속하고 이전 문맥을 전달하지 않은 생성기 20개로 파일럿을 실행했다. 생성기에는 과제별 공개 명세·예제만 전달했다. 두 경로 모두 최초 응답으로 공개 30개와 비공개 684개 입력을 통과했고 수정 호출은 없었다. 모든 공개 생성·수정 과정이 끝난 뒤 최초/각 수정 산출물의 비공개 채점을 하도록 절차를 분리했다.

이 실행은 `session-integration` 검증이다. [실제 판정과 원본](../results/session-validation-2026-10-27/report.md)을 보존한다. 초기 수집 당시 모델 설정·usage·API 원 응답·생성 출력 토큰 상한·모델 요청 시간이 없었으므로 당시에는 단계 E의 통제된 토큰·비용 비교 완료로 취급하지 않았다.

후속 로컬 로그 분석으로 생성기 20개의 모델 별칭(`gpt-6.1-sol`)·추론 설정(`ultra`)과 사용량을 복원했다. 입력 1,824,688토큰 중 캐시는 1,721,088토큰이며 출력은 reasoning을 포함해 5,395토큰이었다. [추가 관측과 집계 범위](../results/session-validation-2026-10-27/usage-recovery.md)를 별도로 기록한다. 초기 `summary.json`의 미관측 값은 측정 시점 기록으로 보존한다. 캐시 적중률과 전달 방식이 달랐으므로 통제 비교 완료로 취급하지 않는다.

이후 별도 버전 `SS-002-BATCH-001`에서 전달 방식과 도구 왕복을 맞춘 10과제 묶음을 경로마다 3회 생성했다. [후속 설계](efficiency-study.md)와 [결과](../results/efficiency-study-v1/report.md)를 분리 기록했다. 두 경로가 모두 통과했고 생성 비용의 캐시 통일 환산은 C가 중앙값 약 8% 낮았다. 이 결과는 독립된 문제 60개에 대한 평가나 일반적인 우월성의 근거가 아니다.

## 9. 완료와 후속 개발 판단

**실험 완료:** 두 경로의 성공·실패·수정 과정을 재현 가능한 형태로 남기고 비교 보고서를 생성한다. WAT가 불리해도 완료다.

**후속 개발 판단:** 별도 평가에서 정확도와 총비용/총시간의 trade-off를 보고 결정한다. 작은 파일럿의 근소한 차이로 우월성을 선언하지 않는다. 반복 실행의 분산과 과제별 차이를 제시하고, 표본이 충분하면 paired 신뢰구간 등 분석 방법을 사전에 정한다.

정확도가 낮은데 출력만 짧아진 결과는 가설의 성공으로 취급하지 않는다. 이득이 없다면 오류 피드백·연산 설계·구조화 IR을 별도의 실험으로 검토한다. AI용 표현의 추가 학습이 필요한지 여부도 기존 모델 그대로의 실험과 분리한다.

API 키나 별도 과금이 필요한 모델 실행은 사용자가 요청한 실행 범위에서 진행한다. 과제 수·예산 상한·평가 반복 횟수 등의 계획과 실제 세션 검증 결과를 구분한다. 세션 검증에서 미관측한 토큰·금액을 0이나 추정 성공값으로 채우지 않는다.
