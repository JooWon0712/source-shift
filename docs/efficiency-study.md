# C/WAT 효율 비교: 토큰을 제한한 묶음 생성 파일럿

실험 ID: `SS-002-BATCH-001`. 기준일: 2026-10-27 (Asia/Seoul).

이 문서는 실행 전에 정한 조건이다. 기존 파일럿의 C/WAT 전달 방식과 캐시 적중률 차이를 줄이면서, 큰 에이전트 문맥을 함수마다 반복하는 소비를 피한다. 별도 API·유료 서비스는 호출하지 않고 현재 세션 모델 설정을 그대로 상속한다.

## 고정한 설계

- 공개 명세와 예제가 같은 파일럿 10개를 한 JSON 응답으로 생성한다. 한 경로의 10개 함수 묶음이 생성 단위다.
- C/WAT 각각 독립 문맥 3개, 총 6개 생성기를 사용한다. 함수 60개를 독립 표본 60개로 해석하지 않는다.
- 순서는 `C/WAT`, `WAT/C`, `C/WAT`이며 직렬로 실행한다. 모든 생성기에 저장된 공개 프롬프트를 직접 전달하고 파일 저장 1회와 완료 응답을 요청한다.
- 초기 생성 1회, 공개 실패 시 묶음 수정 최대 2회다. 모든 시도와 사용량을 보존하고 전체 생성·수정이 끝난 뒤 각 시도의 비공개 채점을 한다.
- 응답 JSON의 바이트 상한은 32,768이다. 앱의 생성 토큰 상한은 도구로 설정할 수 없어 미지원으로 기록한다. 결과를 조용히 잘라 맞추지 않는다.
- 모델·추론 설정은 변경하지 않는다. 로그의 설정과 실제 응답 수·도구 왕복 횟수도 확인한다.

## 판정 기준

첫 응답/최종 정확도와 모든 생성·수정의 출력 토큰(reasoning 포함)을 비교한다. 비용은 실제 청구액과 구분하여 Standard API 단가 환산을 기록한다. 캐시 운에 좌우되지 않도록 모든 입력을 일반 입력으로 계산한 시나리오를 주 비용 지표로 두고, 관측 캐시를 적용한 환산도 함께 제시한다. 적용 모델·단가는 프로토콜과 로그가 일치할 때만 계산한다.

실용적인 주 비용 이점은 최종 정확도가 같으면서 3개 짝 모두 같은 방향이고 중앙값 절감률이 5% 이상인 경우로 정의한다. 5%는 사전에 택한 실용 기준이며 통계적 유의성 기준이 아니다. 미달하거나 방향이 엇갈리면 비용 우열은 불명확하다고 보고한다. 출력 길이, 파일 크기, 생성 시간, 실행 성능을 같은 지표로 바꾸어 주장하지 않는다.

## 로컬 측정

미리 선택한 첫 반복의 10쌍을 사용한다. 변환은 5회 교차 측정하고 최초 warmup은 따로 남긴다. C는 고정 Clang CLI, WAT는 Wasmtime 라이브러리 조립을 사용한다. 두 도구의 호출 구조·최적화가 다르다는 점도 결과의 일부다.

런타임은 같은 Wasmtime/Cranelift 설정에서 JIT·인스턴스 생성과 warm guest batch를 나눈다. warm에서는 공통 Wasm harness가 입력을 읽고 대상 함수를 호출하며 각 결과를 참조값과 비교한다. Python은 묶음마다 한 번 호출한다. 측정에는 공통 harness와 import 호출·검증 overhead가 들어가므로 순수 함수만의 시간으로 해석하지 않는다. 성능 측정에서는 양쪽 모두 fuel을 끄고 부모 프로세스의 시간 상한을 둔다.

외부 CPU 부하는 통제하지 않으며 게임 중지·GPU 생성·상시 감시는 하지 않는다. 반복 결과가 흔들리면 시간 우열을 유보한다. 이 10개는 이미 개발에 사용한 쉬운 과제이므로 결론의 범위는 해당 묶음·모델·실행 방식에 한정한다. 별도 평가 문제에 대한 일반화 결론은 내리지 않는다.

## 기록

프로토콜·프롬프트·응답·모든 오류·공개/비공개 판정·소스와 도구 버전 해시를 보존한다. 로컬 usage를 개별 응답별로 중복 제거해 집계하고 누적값과 대조한다. 캐시 입력과 reasoning은 이미 포함된 총량에 다시 더하지 않는다. 실험 조율·개발 사용량은 생성기 비교와 분리하며 실제 청구액은 미관측으로 둔다. 원시 로그와 개인 경로는 결과 사본에 넣지 않는다.

## 실행 후 연결

[고정 프로토콜과 실제 결과](../results/efficiency-study-v1/report.md)를 저장했다. 각 경로의 3개 묶음 모두 첫 응답으로 통과했고 비공개 사후 채점까지 완료했다. 생성 비용 판정은 C이며 캐시 통일 환산의 절감률 중앙값은 약 8%다. 이는 해당 모델·10과제 묶음에서의 파일럿 판정이다.

생성기 6개의 전달 방식·도구 호출 수는 같았다. 저장한 프롬프트 해시는 보존했지만 로그의 에이전트 간 전달문이 평문으로 노출되지 않아 실제 전달문 전체의 해시를 독립 대조하지 못했다. 이 항목은 일치나 불일치로 채우지 않고 미관측으로 남겼다. 초기 해시 조사도 로컬에 보존했으며 결과를 바꾸기 위한 추가 생성은 하지 않았다.

조율·측정기 구현·분석의 공통 소모가 생성기 자체보다 컸다. [사용량 스냅샷](../results/efficiency-study-v1/resource-audit.json)에 범위와 집계 시점을 구분했다. 별도 유료 API는 호출하지 않았다.
