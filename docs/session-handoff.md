# 작업 정리와 재개 지점

정리 기준일: 2026-10-27, Asia/Seoul.

**사용자의 “여기까지만 작업” 요청으로 신규 실험·조사를 종료했다. 아래 후속 후보는 미착수이며, 이후 사용자 요청 범위에 맞춰 재개한다.**

작업을 시작한 이유와 실제 진행 시나리오, 결론에 이른 논리와 후속 판단은 [프로젝트 종합 정리](project-summary.md)에 자세히 모았다. 이 문서는 파일 위치와 운영상 재개 지점을 중심으로 읽는다.

## 현재 결론

현재 모델 설정(`gpt-6.1-sol`, `ultra`)과 개발용 정수 함수 10개에서는 **C를 기본 생성 경로로 유지하는 판단**이다. WAT의 장점은 조립 속도와 작은 Wasm 파일이었다. 다른 모델·큰 프로그램·새 평가 문제로 일반화하지 않는다.

| 후속 묶음 파일럿의 관측값 | C | WAT |
| --- | ---: | ---: |
| 첫 응답·최종 정답 함수 수 | 30/30 | 30/30 |
| 모델 피드백 기반 수정 횟수 | 0 | 0 |
| 생성 출력 토큰 합계, reasoning 포함 | 2,156 | 4,702 |
| 10함수 생성 에이전트 턴 중앙값 | 23.509초 | 39.682초 |
| 10개 Wasm 파일 합계의 반복 중앙값 | 3,981바이트 | 954바이트 |

- 같은 10과제 묶음을 두 경로로 각각 3회 생성했다. 독립 생성 단위는 묶음 3쌍이며, 서로 다른 문제 60개가 아니다.
- 공개·비공개 사후 평가 **4,284건 모두 통과**했다. 최초 공개 검사 180건은 별도다.
- 입력을 모두 일반 입력 단가로 통일한 가상 API 비용 환산에서 C가 3쌍 모두 낮았다. C 절감률은 8.0%, 8.3%, 4.2%, 중앙값 약 8.0%였다. 실제 청구액 절감률이 아니다.
- 함수당 변환은 C 약 540~660ms, WAT 약 0.5~0.8ms였다. C는 Clang CLI, WAT는 Wasmtime 라이브러리이므로 도구 시작·링킹·최적화 차이도 포함한다.
- warm 실행 시간은 과제별로 방향이 갈렸다. 공통 guest harness와 결과 검사 overhead, 통제하지 않은 외부 CPU 부하가 있으므로 전체 실행 속도 승자는 정하지 않았다.

WAT는 WebAssembly의 텍스트 표현이고 `.wasm`은 바이너리 형식이다. 이번 비교는 `C → Clang → Wasm`과 `WAT → 조립 → Wasm`이다. 모델이 바이너리 바이트를 직접 생성한 실험은 아니다.

## 완료한 구현과 검증

- Python CLI: 도구 버전 확인, 공개 과제 출력, C/WAT 본문 변환·실행·채점.
- 파일럿 P01~P10, 독립 Python 참조 구현, 공개 예제 30개와 비공개 입력 684개.
- 고정 ABI/템플릿, 본문 경계 검사, import·ABI 확인, fuel·wall-clock 제한, 자식 프로세스 종료와 실패 원본 보존.
- 공개 검사와 비공개 사후 평가 분리. 비공개 입력·결과는 생성·수정 프롬프트에 제공하지 않는다.
- 로컬 JSONL usage 복원, 응답별 중복 제거와 마지막 누적값 대조, 캐시·reasoning 이중 합산 방지.
- 변환·JIT·인스턴스 생성·guest-loop warm 측정과 모든 반복의 원본 저장.
- 검증한 테스트는 총 **64개**다. 기존 전체 62개 통과 후 비용 집계 테스트 2개를 별도 실행해 통과했다. 이번 마감 정리에서는 실험·테스트를 재실행하지 않았다.

도구는 프로젝트 `.venv`의 Python 3.12.14/Wasmtime 50.0.1과 `.tools/llvm-23.1.4`의 Clang/LLD 23.1.4다. 기본 `python` 명령은 Windows 실행 별칭이므로 실제 작업에는 `.venv/Scripts/python.exe`를 사용했다.

## 비용과 해석의 제한

- 별도 유료 API는 호출하지 않았다. 실제 Codex 청구액·한도 차감량은 미관측이다.
- 후속 생성기 6개만의 사용량은 **405,917토큰**이다. 공통 조율기·측정기 구현·주 에이전트 분석은 여기에 포함하지 않는다.
- 공통 작업을 포함한 기록 스냅샷은 **15,168,909토큰**이다. 입력 대부분은 반복 집계된 캐시 문맥이며, 기록 시점 이후 보고·대화·마감 정리는 포함하지 않는다. 이를 전체 세션의 최종 총량으로 표현하지 않는다.
- 모델 별칭과 추론 설정은 확인했지만 백엔드 snapshot, 공급자 출력 토큰 상한과 순수 API 요청 지연은 미관측이다. 위 생성 시간은 도구·대기·완료 보고를 포함한 에이전트 턴 시간이다.
- 프롬프트 저장본과 조율 ledger는 보존했다. 전달문이 로그에 평문으로 남지 않아 전체 전달문 해시의 독립 대조는 미관측으로 기록했다.
- 모델 생성물은 모두 첫 응답으로 통과했다. 따라서 **실제 모델의 버그 수정 효율과 기능 변경 효율은 아직 비교하지 않았다.** 의도적인 실패 처리 테스트와 모델 기반 수정 성과를 구분한다.
- 부동소수·직접 메모리·재귀 등 제외 기능의 완전한 정적 검사는 없다. 현재 실행기는 검토한 파일럿 대상이며 OS 수준 컴파일러 보안 sandbox를 제공한다고 주장하지 않는다.

## 논의만 한 후속 후보

| 후보 | 조사 내용과 남은 점 |
| --- | --- |
| SimPy | Python과 같은 AST를 유지하는 축약 문법 연구. 현재 모델에서의 총비용 절감은 미검증 |
| Token Sugar | 반복 패턴 약어와 추가 학습 연구. 보고된 최대 11.2%는 생성 코드 표현 토큰 절감이며 전체 작업 비용이 아님 |
| Tacit | AST 원본과 AI용 압축/사람용 검토 표현을 제공하는 공개 구현. 이 저장소에서는 미실행 |
| 작은 고수준 수식/DSL | 직접 설계할 수 있는 실험 후보. 어휘·규칙 설명 비용과 C 기준선의 동등한 연산 기능을 함께 통제해야 함 |
| diff·AST 편집 명령 | 전체 재생성 대신 변경 부분만 표현하는 수정 후보. 아주 작은 함수에서는 부가 문법이 더 길어질 수 있음 |

근거와 링크는 [참고 자료](references.md)에 정리했다. 새 표현 개발·추가 학습·새 모델 연결·기능 변경 실험·별도 평가 문제·raw binary 생성은 착수하지 않았다. 후보는 확정된 개발 계획이 아니다.

## 재개할 때

1. README와 이 문서, 후속 결과 보고서를 먼저 읽고 기존 산출물을 활용한다.
2. 사용자 요청에 맞춰 다음 질문 하나와 예산을 정한다. 설계·실행·분석은 주 에이전트가 맡고 별도 비용은 실행 전에 알린다.
3. 새 실험이면 새 버전으로 조건을 먼저 고정한다. 기존 비공개 결과를 추가 생성·수정 피드백으로 사용하지 않는다.
4. 작은 측정 단위를 택하고 반복 문맥·조율 비용을 포함한다. 기존 실험을 자동 반복하거나 로컬 대화 LLM을 복구하지 않는다.

2026-10-27 마감 시점에는 파일이 작업트리에 저장되어 있었고 Git 커밋·push 전이었다. `.venv/`, `.tools/`, `.runs/`도 보존했으며 정리만을 위해 코드·도구·실험 원본을 삭제하지 않았다.

2026-10-28 사용자 요청으로 [공개 GitHub 저장소](https://github.com/JooWon0712/source-shift)에 코드·문서·정리된 결과를 보관하는 작업을 추가했다. 로컬 환경·도구·원시 로그는 Git 추적에서 제외한다. 최신 커밋·게시 상태는 Git 이력과 원격 저장소를 기준으로 확인한다. 새 모델 실험은 재개하지 않았다.
